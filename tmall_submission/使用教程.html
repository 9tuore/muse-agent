# Muse 使用教程（GOSIM / 参赛版）

适用：Muse 0.3.27-rc10 配套运行包，Intel Mac，macOS 14 或更新版本。教程不包含账号、授权码或 API Key；两版使用同一套 Muse 核心，但分别保存自己的体验资料。

## 1. 先打开应用

**参赛版：**完整解压 Muse-Tmall-Submission.zip，双击文件夹里的 Muse.app；也可双击 RUN_MUSE.command。内置基础离线模型随入口启动，无需填 Key、安装 Python 或另下载模型。首次会打开应用中心：找到 Muse，确认安装，再点打开。以后入口直接进入 Muse。

**GOSIM 完整包：**完整解压交付 ZIP。若外层包含“00-展开并启动.command”，先运行它，等待校验及完整展开；不要直接打开未展开的内部压缩文件。当前 rc10 两版都可直接双击 Muse.app。首次同样在应用中心安装并打开 Muse。以包内“先看这里”教程和来源清单为准。

如果 macOS 提示来源未验证，只在确认作品来源可信后，按系统提供的“系统设置 → 隐私与安全性 → 仍要打开”流程决定是否继续。不要关闭 Gatekeeper 或执行去除安全保护的脚本。[Apple 官方打开说明](https://support.apple.com/zh-cn/102445)

## 2. QQ 邮箱授权码在哪里获得

授权码用于第三方客户端登录，与 QQ 登录密码不同。Muse 的“授权码”栏要填它，不能填 QQ 密码。

1. 用浏览器打开 [QQ 邮箱网页版](https://mail.qq.com/)，登录自己的账号。手机版若找不到相关设置，可切换标准版或使用电脑网页。
2. 进入“设置 → 账号与安全 → 安全设置”，查找“POP3/IMAP/SMTP/Exchange/CardDAV/CalDAV”相关服务；部分旧界面在“设置 → 账户”中。
3. 开启 **IMAP/SMTP** 服务，然后选择生成授权码；按 QQ 邮箱当前页面要求完成本人安全验证。验证方式可能随账号、地区和界面版本不同，不要把短信验证码交给他人。
4. 将页面生成的授权码填入 Muse 的宿主登录窗口。若未保存或已失效，在服务设置中管理或重新生成，并更新 Muse 登录。不要把授权码写进聊天、截图、GitHub 或交付包。

QQ 官方帮助入口：[QQ 邮箱帮助中心](https://service.mail.qq.com/cgi-bin/help)。本次该帮助页未能通过自动读取取得正文；上述常见网页路径参考 [华为官方 QQ 邮箱登录支持](https://consumer.huawei.com/cn/support/content/zh-cn00696857/)，具体按钮以你的 QQ 邮箱当前页面为准。

## 3. 在 Muse 连接 QQ 邮箱

进入左侧“邮箱”，点“连接账号”。宿主表单只需完整邮箱地址与授权码；不要只填 QQ 号码，也不用额外填写用户名。

| 项目 | 填写内容 |
| --- | --- |
| 邮箱地址 | 你自己的完整 QQ 邮箱地址，包含 @qq.com |
| 授权码 | 第 2 节生成的第三方客户端授权码 |
| 收件协议 | IMAP |
| 收件服务器 / 端口 | imap.qq.com / 993 |
| 收件加密 | TLS / SSL |
| 发件服务器 / 端口 | smtp.qq.com / 465 |
| 发件加密 | TLS / SSL |

登录后返回邮箱页，刷新或同步收件箱。首次启用会记录已有邮件基线；请从另一个邮箱发一封新测试信，再观察聊天右侧来信卡。Muse 与配套 OctoSense 窗口需要保持运行，关闭应用后自动查看新邮件也会停止。

**回复：**在来信卡展开正文，选择回复，填写你想表达的意思后起草；也可选择自己写回复。检查收件人、主题和正文，再点击明确的发送确认。选择“不予回复”只处理这张卡，不会发送。草稿/服务受理不等于收件端收到；需要时在收件端独立核对。不要因短暂等待就重复点发送。

## 4. 授权真实系统日历

1. 先确保 macOS 自带“日历”中已有你准备使用的可写日历。
2. 在 Muse 左侧“日历”，点击“请求完整日历访问”，在系统弹窗自行选择允许。
3. 如果以前点过拒绝，或仅允许添加：到“系统设置 → 隐私与安全性 → 日历”，找到本次运行的 OctoSense 宿主，按系统的选项调整为**完全访问**。Muse 的冲突查询和独立读回需要读权限，仅添加权限不足。[Apple 日历权限说明](https://support.apple.com/zh-hans/guide/mac-help/mh43710/mac)
4. 回到 Muse，点击“刷新宿主授权状态”，选择目标日历。名字不一定叫“工作”，选择你自己的实际日历。
5. 点击日期或在聊天提出明确的未来日期、起止时间和时区；先检查候选与冲突，再按确认卡操作。修改、删除和不明确安排继续确认。到 macOS 日历核对结果；外部修改后，在 Muse 刷新对应范围。

只有本次宿主有对应日历服务及能力准入时才可操作。更换宿主签名后，系统可能将它视为新应用，需要重新授权；模型回答“完成”不能替代系统日历中的实际事件。

## 5. 聊天、记忆与项目

在中间输入区直接提问。左侧切换或新建对话，右侧查看来信、候选与结果；需要时可收起侧栏。新对话仍可检索同一授权用户的相关全局记忆。

先核对当前项目与资料归属再保存记忆。明确说出“记住”“更正”或“忘记”的内容，完成后在“记忆”页检查保存项、来源和状态。冲突需要核对，不能把老师项目、个人项目或未授权邮箱资料混为一谈。删除对话与遗忘全局记忆是两个动作。

## 6. 离线模型与更强模型

内置模型无需登录模型账号，只适合基础离线体验；短格式指令和复杂安排仍可能误答，不保证强模型效果。云端模型不会随包附带他人的 Key。

需要更强模型时，在 OctoSense“AI 模型设置”选择支持的 Provider，填写自己的有效配置；密钥只填官方设置。参赛入口也可用“RUN_MUSE.command --models”打开设置。选择云端后，入口保留你的配置；不会强制切回内置模型。可能收费的模型先核对自己的服务商计费。

模型、邮件和日历权限各自独立：能聊天不代表邮箱已登录，邮箱登录不代表日历已授权。

## 7. 常见问题

| 提示 / 现象 | 处理方法 |
| --- | --- |
| NO Login fail. Please input email address | 填完整邮箱地址，核对授权码与 IMAP/SMTP 已开启；不要只填号码或另外填用户名。 |
| 账号密码缺失，请重新登录 | 在当前宿主“连接账号”重新输入授权码；不要删聊天历史或生产资料。 |
| 无法连接邮箱服务器 | 检查上表地址、端口、TLS、网络与邮箱服务状态；不把授权码发给支持人员。 |
| 看不到新来信卡 | 保持 Muse/OctoSense 运行，先确认账号同步成功，检查是否是启用后的新信；展开右侧结果区。 |
| 没有日历 / 不能查冲突 | 检查完整访问、目标日历可写性及宿主服务；返回 Muse 刷新。 |
| 模型返回 HTML 或调用失败 | API 地址应指向服务商真实模型 API；网页地址不是模型接口。凭据有效性在官方设置核对。 |
| 提示应用已运行 | 切回已有窗口；要重开时先正常退出配套 OctoSense，不强行开启第二份。 |
| 需要重新下载包 | 使用完整 ZIP，不单独复制 Muse.app 内某个二进制。解压大小大于 ZIP 大小是正常现象。 |

需要帮助：[项目 Issues](https://github.com/9tuore/muse-agent/issues)。只提供版本、设备、错误文字和脱敏截图；不要提交授权码、Key、私人邮件或本机资料目录。


## 8. 来信自动安排（0.3.27）

先连接本人邮箱，授予完整日历访问，并核对当前项目、资料归属和目标可写日历。在邮箱页选择“授权当前邮箱与项目自动安排到所选日历”。这一授权只覆盖该账号、项目、归属及目标日历的新约定；来信本身不能扩大授权。

新邮件可只提供日期：同项目记忆中已有时区、约定时长和偏好时段时，Muse 会提取候选，核对该目标日历的真实冲突，自动新建并独立读回。缺资料、冲突或超出范围时仍会询问。后续改期修改关联的原事件；发信、修改与删除保留各自确认。可随时点击“暂停来信自动安排”。
