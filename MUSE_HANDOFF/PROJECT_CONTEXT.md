# Muse 项目定位

Muse 是面向 GOSIM Agentic App 2026 的 Local-first、长期常驻个人 Agent Runtime。用户面对一个统一的 Muse 对话与结果入口，而非自行选择一组内部 Agent。它的目标是在用户明确授权的范围内理解电脑状态、消息、日历、文件、浏览器、应用、长期 Goal 与历史 Memory，并把意图转成可检查、可执行、可验证的行动。当前优先交付 macOS 原生桌面应用；OnePlus 6 可以成为后续移动测试节点，不属于现有成品能力。

预期工作链是：事件感知 → 意图理解 → 规划 → 必要时升级高阶模型 → Policy 检查 → Capability 执行 → 结果回读验证 → Memory 更新 → 主动汇报。模型负责思考和提出候选动作，Capability 负责受限执行，Policy 决定是否允许。高风险动作必须由用户看到对象、范围和后果后确认；模型输出、邮件正文和网页内容都不能替用户批准。默认不把无限制 shell 交给模型，也不把“能读一个目录”解释为理解整台电脑。

本地轻量模型承担日常路由与低成本处理，复杂任务可经用户配置的高阶模型处理。长期方向是允许用户配置多个 Provider，一次保存一个 Provider 的 API Key，由 Muse 内部复用，并选择 Primary / Backup、模型、推理强度与预算；这类似 CC Switch 的配置体验，并不意味着目前已有同等产品能力。API Key 只能存入系统安全存储，不进入 Memory、DSL、日志、Git 或插件。远程请求应在有明确费用、资料外发预览和预算边界时执行。

Goal、Memory、Capability 是同一 Muse DSL family 的三种文档。DSL 首先给 Agent 和运行时使用；人可以在“查看计划/技术详情”核对来源、动作、摘要与授权范围。长期 Goal 是 v0.1/v0.2 的核心，应支持只读草案、明确批准、时间或事件触发、暂停、取消与重启续行。Memory 不是原文件全文：事实 Fact 与推断 Inference 必须区分，并保留 Entity、Relation、Source、Confidence、Time 和账号范围，支持更正、遗忘与来源追溯。

能力最终应允许第三方插件扩展，也允许 Muse 通过观察应用界面学习受限的新操作：观察控件、提出配方、审批、试运行、读回验证、保存可复用映射。这样的学习必须有真实 UI 观察和动作证据，不能把写死的宏称为通用学习。外部应用优先使用稳定 API，其次使用 UI Tree / Accessibility，再考虑受限 Terminal，最后才用视觉。普通用户最终应从 `.dmg` 安装和首启配置，不需要打开开发终端。

OctoSense 是比赛适配层和宿主相关入口，须与 Muse Core Runtime 解耦。比赛还涉及 robrix2 等官方组件；本项目的本地 AppKit 应用、Python worker 或本地结果卡不能自动算成官方 AppCard、robrix2 会话或官方确认回传。官方接入是否完成，要看同一任务的真实宿主会话、人工确认、受限动作、独立回读和结果回传。不能因为源码编译、窗口出现或本地 fixture 通过就宣称比赛全链完成。

用户体验上，Muse 应能常驻但在空闲时低消耗。来信、文件变化或明确的时间触发后，它先判断事件是否值得打扰，再把需要用户决定的事项整理成结果卡和通知。用户可以直接聊天追问、改变目标、暂停、取消、撤销授权，或指定某个联系人开始回信；回答应解释依据与下一步，不能代替用户决定邮件正文、费用或敏感动作。界面主要呈现结果和待选择事项，执行细节可在技术详情中追溯。主动性应可配置，不应把每次扫描都变成模型调用或通知。

数据边界同样属于产品定义。消息、网页、文件和应用界面都是可能不可信的输入：它们可以成为待分析的来源，不能升级成系统指令。Memory 应有来源与时间，允许用户更正、固定、禁记或遗忘；检索结果要受账号和工作区范围约束。所有实际动作应留下可核对收据，包括使用了哪项能力、操作对象、批准依据、读回结果和失败状态。失败或断连时应明确停在等待或阻塞状态，不能用语言上的“完成”掩盖未发生的动作。

比赛路线要求把本地产品价值与官方宿主验收分别维护。Muse 可以先在 macOS 上验证事件、Goal、能力、模型和交互，但比赛级证明还需按官方组件真实运行，核对会话身份、用户确认、授权范围、动作唯一性、结果回传及拒绝、过期、重放等反例。架构允许以后替换模型、添加 Capability 或接入移动设备，同时维持同一 Policy/Verify 边界；新增 Provider 或新软件不应迫使用户换一个 Muse，也不应推倒已有 Runtime。

**当前已完成的范围**是本机原生 Muse、驻留 worker、本地 Qwen、受限 Goal/Memory/Capability 基础、QQ 邮箱监听与确认回复等可验证路径；具体版本、测试和缺口只以 [CURRENT_STATE.md](CURRENT_STATE.md) 为准。**最终愿景**还包含可分发给陌生用户的安装体验、真实高阶模型验收、更多电脑与移动能力，以及完整官方宿主链。开发时必须始终把这两层分开。
