1. 开始运行

本草稿以 Intel / macOS 14 或更新版本 为复现测试门槛。Calendar 完整访问分支要求 macOS 14+；Host 的 Mach-O 最低字段为 10.12，不能用该字段代替功能兼容实测。每台预留至少 1 GiB 空间。

  1. 传送完整 ZIP，双击解压。整个文件夹可以移动到含中文和空格的路径；不要只拷贝 Host.app，也不要在 ZIP 预览中运行。
  2. 双击 02-系统检查.command。它只核对系统与包内文件，不创建 profile，不读取账号。
  3. 双击 01-启动Muse.command，保留终端窗口。宿主打开后进入应用中心，确认 0.3.26-rc18，阅读能力请求并安装，再从“已安装”打开 Muse。签名 catalog 的历史记录不表示旧载荷也已附带。
  4. 按 F10 / Fn+F10 进入官方模型设置，创建或选择本机自己的配置，测试模型并保存首选项。未配置模型前，不把窗口出现算作问答成功。

若系统阻止打开，按针对这份开发应用的“隐私与安全性”提示确认。包内 Host/Card 是 ad hoc 开发签名，未 Apple 公证；本次未自行重签。

启动壳会在接收机新建独立数据目录，使用隔离环境，不预置 provider、密钥或模型权重。正常退出使用宿主菜单或 ⌘Q；终端窗口关闭会终止本次宿主。

2. 每台分别配置与授权

  • 模型：两台使用相同模型、线路和参数，各自用本人账号配置。先做两个不同的短问答，保留真实原始回答与耗时。
  • 邮箱：进入官方邮箱设置，由本人登录并处理 macOS Keychain 提示。先确认同步状态，再考虑本人授权的测试操作；待执行、等待宿主或弹窗不算发送成功。
  • 日历：本人处理系统 Calendar 权限提示。若请求超时或状态仍为 not_determined，先在系统设置核对授权，退出重开，再读取状态；不要把超时计作授权成功。仅在确认 full_access 后使用专用测试日历，由本人确认测试动作并核对系统读回。

本包没有发送机 profile、账号、Keychain、邮箱、数据库、模型 config 或权重。复现产生的数据留在各机，不将整目录外传。

3. 双机记录

打开 03-双机复现记录.txt，分别填写 Mac A/B：系统版本、包检查、实际安装版本、模型两问、合成记忆召回与更正/遗忘、一次性测试任务、退出重开、电脑重启和本人授权的邮箱/日历选测。每项写 PASS / FAIL / 未测，记录失败原文；窗口、卡片或“确认”点击不能代替外部动作证据。
